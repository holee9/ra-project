# QA·검토 게이트 (Reflection Gate) — #98

> 최종 갱신: 2026-10-28 (§2-0 사실성 게이트 선행 의무·§3 포맷 규격화·§4 보유율 KPI 신설) / 2026-06-09 (#98 도입)
> 마스터 헌장 §3의 실행 절차. 작성(도메인 페르소나)과 검토(QA·검토관)를 분리해 자가작성=권위를 차단한다.

## 1. 원칙
- **작성자 ≠ 검토자.** 회차에서 문서를 작성한 도메인 페르소나(MFDS/FDA/MDR/표준)와, 그것을 검증하는 QA·검토관은 분리된 판단으로 동작한다.
- 검토 미통과 산출물은 **커밋 금지**(반려 후 재작업).

## 2-0. 선행 의무 — 기계 검증 (2026-10-28 신설)

사람 검토(§2) **이전에** `python3 .ra-scheduler/verify_facts.py --files <대상>` 을 통과해야 한다(SOP §2-E).
산문 체크리스트만으로는 규제 식별자 오류가 통과한다는 것이 2026-10 실측으로 확인됐다.

## 2. 검토 체크리스트 (QA·검토관 수행)
1. **근거**: 1차 공식 출처 ≥3개, URL 유효, 발효·개정일 명시.
2. **최신성**: 2024~현재 기준 최신 개정 반영(QMSR 2026-02-02·EUDAMED 2026-05-28 등 기준선 대조).
3. **구조**: Fact/Interpretation/Action 3계층, 3지역×3제품 매트릭스(해당 시).
4. **정합성**: 기존 KB와 상충·중복 없음(INDEX 대조).
5. **추정 표기**: 미확정은 `[검증 필요]`로 명시 + VERIFICATION_REGISTER 등록.

## 3. 판정·기록
각 신규·갱신 문서 하단에 검토 라인 삽입. **아래 포맷을 그대로 쓴다 — 기계 파싱 대상이다.**
```
---
작성: <페르소나> · 검토(QA): <근거 재확인 요약> · 사실성게이트: <pass|offline|해당없음> · 상태: <승인|조건부|반려> · 일자: YYYY-MM-DD
```
- `상태:` 값은 대괄호 없이 세 값 중 하나만 쓴다(종전 `[승인|조건부|반려]` 표기 혼용이 집계를 막았다).
- `조건부`는 사유를 괄호로 덧붙인다: `상태: 조건부(사람확인 대기 — 사유)`.
- **승인**: 5개 항목 충족.
- **조건부**: 사람 최종 사인오프 필요(예: 회사 내부수치·전략판단) → `조건부 — 사람확인 대기`.
- **반려**: 미충족 항목 명시 후 재작업.

## 4. KPI 연동
- 근거 정확도(=승인 중 근거충족률) 100% 목표, 검토 반려율·재작업 건수 STATE_maintenance에 기록.
- **검토 라인 보유율** — 분기 회차가 실측해 STATE·대시보드에 기록한다. 2026-10-28 기준선 **41/126 = 32.5%**.

